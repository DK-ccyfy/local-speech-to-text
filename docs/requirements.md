# 需求理解与功能拆分（requirements.md）

本文档记录对考核题目的需求理解、功能拆解、关键假设与边界条件。原始题目见考核说明，此处不全文复述。

## 1. 需求理解

构建一个可独立复现、可实际运行、带自动化测试的小型 B/S 语音识别产品：

1. **本地优先**：识别必须由本地开源 ASR 模型完成（CPU 可跑、权重可提前下载、运行期可断网），禁止云端 ASR API 与浏览器 Web Speech API；
2. **两条输入路径，一个后端**：浏览器麦克风录音（≤60 秒，录完再识别）与音频文件上传（WAV 必须支持）共用同一条 `POST /api/transcribe`；
3. **接口契约固定**：`/health`、`/api/transcribe`、`/`，返回字段与 4xx/5xx 语义按题目执行；
4. **工程质量同等功能**：异常处理矩阵、pytest 自动化测试（区分 Mock 与真实模型）、样本音频、完整文档与统一启动/测试命令。

## 2. 功能拆解

### F1 麦克风录音（必做）
- `getUserMedia` 请求权限；开始/停止按钮与状态机（空闲→录音中→识别中→完成/失败）；
- 录音时长实时显示（基于采样点计数，精确到 0.1 秒）；
- **60 秒硬上限**：前端定时器检测，达到上限自动停止并提示；
- 权限被拒（NotAllowedError）、无设备（NotFoundError）、设备占用（NotReadableError）分别给出可读提示，页面不崩溃；
- 一次识别完成后状态复位，可立即再次录音。

### F2 文件上传（必做）
- 至少支持 WAV；同时支持 WebM/Opus（浏览器 MediaRecorder 常见格式）与 MP3（后端 PyAV 统一解码，天然支持）；
- 前端预检（扩展名、空文件、10 MB），后端强制校验（大小 413、解码失败 400）；
- 与录音共用 `/api/transcribe`（前端把录音编码成 WAV 后走同一上传函数）。

### F3 本地中英文识别（必做）
- 模型：faster-whisper `small`，CPU int8（选型理由见 design.md）；
- 页面语言选择：中文 / English / 自动检测（加分）；
- 首次运行联网下载权重（HuggingFace 缓存），此后断网可用；
- 不做语音翻译：中文语音出中文文本，英文语音出英文文本。

### F4 结果展示（必做）
- 当前语言、状态徽章、识别文本、音频时长（服务端返回）、处理耗时；
- 复制按钮（clipboard API + execCommand 降级 + 「已复制」反馈）；
- 全程状态反馈：录音中有计时与红点动画，识别中有「识别中…」徽章，无长时间无提示窗口。

### F5 异常处理（必做）——映射表

| 场景 | 实现 | HTTP/表现 |
|---|---|---|
| 拒绝麦克风权限 | 前端捕获 NotAllowedError | 页面提示，不崩溃 |
| 无可用麦克风 | 前端捕获 NotFoundError | 明确错误提示 |
| 空文件/损坏音频 | 后端解码失败 / 前端预检 | 400 + 中文原因 |
| 格式不受支持 | 前端扩展名预检 + 后端解码兜底 | 400 + 明确提示 |
| 录音超 60 秒 | 前端自动停止 | 提示「已达上限自动结束」 |
| 模型加载失败 | 服务状态 failed | `/api/transcribe` 503 + 原因 |
| 识别中后端出错 | 异常映射 | 500/503 + detail，前端提供重试按钮 |
| 音频无语音 | VAD 过滤后空文本 | 200 + 空结果（页面显示「未识别到语音内容」） |
| 上传超 10 MB | 流式读取截断 | 413 |

### F6 实时语音识别（加分）
- 录音期间每 3 秒将**当前累计的整段音频**编码为 WAV 发送到同一接口做重识别，页面持续刷新「实时预览」；
- 停止后做最终完整识别。整段重识别避免了分片切断词语的问题；60 秒上限下最大请求约 1.9 MB；
- 请求串行化（上一轮未返回则跳过本轮），预览失败不打扰用户。

### 自动语言检测（加分）
- `language=auto` → 不指定语言交给 Whisper 检测；对中英混合属尽力而为（模型按整体检测语言，段落级混合可能不完美），已在文档说明。

## 3. 关键假设与边界条件

1. **并发**：单用户、单 worker 场景（题目明确不要求多用户并发）；模型单例 + 线程池推理。
2. **上传时长**：题目仅限制文件大小（10 MB），未限制上传音频时长；约对应 16 kHz WAV ≤ 5 分钟，识别可正常完成但耗时按比例增长。
3. **截断但可部分解码的文件**（如传输中断的 WAV）：FFmpeg/PyAV 容错解码有效部分，系统按可识别内容返回结果；完全无法解码才报 400。已在测试报告中说明该取舍。
4. **浏览器录音格式**：前端直接采集 PCM 并编码 WAV（16 kHz/单声道/16-bit），因此「前端实际使用的录音格式」即 WAV；后端仍额外支持 WebM/MP3 以增强上传兼容性。
5. **HTTPS**：题目明确 localhost 场景，不配置证书；麦克风权限在 `127.0.0.1`/`localhost` 下可用。
6. **模型下载**：仅首次初始化需要联网；权重缓存在用户目录（`~/.cache/huggingface`），不进入仓库；支持 `HF_ENDPOINT` 镜像加速。
7. **处理耗时口径**：`processing_seconds` = 解码耗时 + 模型推理耗时，**不含**模型加载/下载时间（模型加载在服务启动时后台完成）。
8. **识别结果评价**：ASR 输出可能包含标点/简繁差异，真实模型测试以关键词重合度断言而非逐字一致。

## 4. 明确不做（题目第 8 节范围外）

登录与权限、数据库存储、历史记录、说话人识别、降噪算法、语音翻译、TTS、模型训练/微调、分布式部署、移动端适配、商业级实时字幕。
